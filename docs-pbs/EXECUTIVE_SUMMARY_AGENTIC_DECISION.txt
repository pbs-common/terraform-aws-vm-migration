================================================================================
THE HONEST BUSINESS CASE FOR AGENTIC WORKFLOW
================================================================================

WHAT WE GET (Real, Verified Value):

1. BULK REHOSTING ORCHESTRATION
   • Client-managed agent installation: manual agent deploy to 49 servers
     (AWS Transform officially supports "Deploy replication agents on your own" option)
   • Transform-managed coordination: test/launch phases, wave sequencing, cutover
   • Unified orchestration UI persists: single pane of glass for all 49 servers
   • Coordinated test/launch phases across waves (vs manual per-server timing)
   • Built-in approval gates at each decision boundary (review → test → cutover)
   • Reduces manual coordination overhead for 3-person team

2. LEGACY OS FLEET DE-RISKING (Where Applicable)
   • 3 Windows Server 2008 R2 servers being migrated
   • Strict prerequisites required for these 3 servers:
     - .NET Framework 4.5+
     - Service Pack 1 + SHA-2 KB updates (most common failure point)
     - WMI service active
     - MBR system drives only
   • Agentic workflow enforces structured validation + approval gates
   • Built-in gates ensure prerequisites tracked and approved before cutover

3. BUILT-IN APPROVAL GATES
   • Several formal checkpoints where workflow pauses for human review
   • Removes need to design custom approval workflow (Jira, email, spreadsheets)
   • Particular value: Gate between wave confirmation and execution ensures
     prerequisites validated + approver sign-off before replication starts

WHAT WE DON'T GET (or don't claim):

❌ Re-discovery or re-planning
   → Wave plan from mapplanner is imported as-is; no re-analysis

❌ Automatic dependency re-detection
   → Importing existing plan doesn't trigger new dependency analysis
   → Dependency data comes from mapplanner discovery (already done)

❌ Additional safety/rollback capabilities
   → Rollback is built into MGN engine (both console and agentic paths have it)
   → No safety difference between console and agentic

❌ Fabricated time savings
   → Estimated time reduction is illustrative, not product-guaranteed
   → Actual time savings depend on your team's manual coordination overhead

================================================================================
DECISION FRAMEWORK
================================================================================

Use Agentic Workflow IF:
   ✓ Any legacy OS servers (e.g., 2008 R2) in scope require coordinated validation
   ✓ 3-person team needs orchestration/gate structure for 49-server migration
   ✓ Coordinated test/launch phases + approval gates valuable at your scale
   ✓ Want single UI for monitoring all server migration status during replication

Use Console Direct IF:
   ✓ Team prefers manual control at each step
   ✓ Have separate tooling/processes for approval gates
   ✓ Simple waves with few dependencies (can coordinate manually)

================================================================================
STEP-BY-STEP EXECUTION PLAN (Self-Registration Path)
================================================================================

ONE-TIME SETUP (before Wave 1):

1. Initialize AWS Transform MGN Service in target account
   • Enable service and set up permissions ("Set up service permissions" step)
   • This enables the console to receive agent registrations

2. Connect target AWS account + get administrator approval
   • Approver: [TBD - AWS admin] confirms target account access
   • Approval gate: blocks launch until this is signed off

3. Validate target networking is in place
   • Your team's responsibility: Confirm VPC/subnets/security groups exist
   • (You skip Transform's "Migrate network" phase; AWS team owns topology)
   • Verify target staging/replication network accessible from client servers

4. Provide client with agent install runbook
   • Include: AWS Replication Agent installer + legacy installer for 2008 R2 servers
   • Include: Prerequisites checklist (.NET 4.5+, SP1, SHA-2 KB, WMI, MBR)
   • Include: Target network access details (VPN, security group rules, etc.)
   • Note: Client does NOT pass user-provided-id (self-registration handles mapping)

PER-WAVE PROCESS (repeat for each wave 1-4):

1. Client installs agent on that wave's servers
   • SSH/RDP to each server, run MGN agent installer
   • For 2008 R2: use legacy installer (AwsReplicationWindowsLegacyInstaller.exe)
   • Servers self-register in AWS Transform MGN console automatically
   • (No your-team action required; agents connect and appear in console)

2. Assign servers to applications and waves
   • Option A: Import your mapplanner wave plan CSV ("Import and export" → Import)
              This bulk-assigns servers to applications/waves/wave order
   • Option B: Manually assign servers in Transform console UI
   • ✓ Servers already in console (from self-registration); just grouping them

3. Review replication status in Transform UI
   • Single pane of glass showing all servers' replication progress
   • Resolve any replication alerts before proceeding
   • Initial sync completion is your checkpoint to proceed

4. Launch test instances + validate + approve
   • Transform launches all wave's servers' test instances together
   • Your team + application owner validate test environment
   • "Mark applications ready for cutover" gate in UI (approval checkpoint)

5. Launch cutover instances + finalize
   • Transform orchestrates final cutover for the wave
   • Finalize cutover to cut traffic to source servers
   • Complete = wave done; move to next wave

ONGOING MONITORING:
   • Single console view for all waves' replication, test, and cutover status
   • Repeat steps 5–9 (Per-Wave Process) for each wave

KEY INSIGHT: Self-Registration Path
   ✓ Simpler than pre-matching approach: no user-provided-id tracking needed
   ✓ Servers self-register when agent connects (automatic mapping)
   ✓ Just assign/group them in Transform after they appear
   ✓ No risk of duplicates (don't mix pre-matching with self-registration)
   ✓ No need to export/re-import IDs before agent installation
