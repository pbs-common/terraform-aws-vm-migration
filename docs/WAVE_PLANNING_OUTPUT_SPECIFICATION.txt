================================================================================
WAVE PLANNING OUTPUT & HANDOFF SPECIFICATION
================================================================================

STORY: AWS Transform Migration Methodology Decision
PURPOSE: Define what the wave planning stage produces and how it flows to the 
         wave plan story for execution planning

================================================================================
WAVE PLANNING DELIVERABLES
================================================================================

Two CSV files are produced during Transform's "Wave Planning" phase:

1. WAVE PLAN CSV
   ├─ Format: CSV (Excel-compatible)
   ├─ Columns:
   │  • Application (name/identifier)
   │  • Application Grouping (which servers belong together)
   │  • Wave Assignment (which wave: Wave 1, 2, 3, 4, etc.)
   │  • Wave Sequencing (order waves execute)
   │  • Dependencies (identified relationships between applications)
   │  • Any custom columns added during review
   │
   ├─ Important: Only rows with BOTH "application" AND "application wave" 
   │            populated are included in the actual migration plan
   │            (blank rows are dropped during processing)
   │
   └─ Source: Transform console → "Generate application groupings and waves" 
             → "Download file"

2. INVENTORY CSV
   ├─ Format: CSV (Excel-compatible)
   ├─ Columns:
   │  • Hostname / Server
   │  • Instance Type Recommendation (Transform's AI recommendation)
   │  • Optimized Instance Type (alternative sizing)
   │  • CPU/RAM/Storage specifications
   │  • Pricing estimates
   │
   └─ Source: Transform console → "Confirm inventory" → "Download file"

================================================================================
WHAT TRANSFORM'S WAVE PLANNING DOES NOT EXPORT
================================================================================

⚠️ NOT included as explicit CSV columns (but DID inform the AI grouping logic):

- Risk Level per application/wave (Transform uses risk internally to distribute 
  complex apps across waves, but doesn't export a "risk_score" column)
  → CUSTOMIZATION: Add your own risk rating column during review/refinement

- Estimated Cutover Time per wave (Transform factors capacity constraints but 
  doesn't provide explicit "cutover_minutes" estimates)
  → CUSTOMIZATION: Add time estimates based on your team's historical data

- Pre/Post-Migration Validation Steps (Transform doesn't generate test scripts 
  or acceptance criteria)
  → CUSTOMIZATION: Add validation requirements during review phase

================================================================================
THE REVIEW & REFINEMENT PROCESS
================================================================================

Step 1: Transform Produces Wave Plan
   └─ CSV exported with default groupings and wave sequence

Step 2: Download & Open in Excel
   └─ Stakeholders review wave plan CSV + inventory CSV side-by-side

Step 3: Business Validation & Customization (ALLOWED)
   ├─ Verify application dependencies are correct
   ├─ Check wave sequencing aligns with business priorities
   │  (e.g., "run Wave 1 + 2 in parallel instead of sequential")
   ├─ ADD CUSTOM COLUMNS:
   │  • Risk Level (e.g., "Low", "Medium", "High")
   │  • Estimated Cutover Time (minutes)
   │  • Pre-Migration Validation (checklist/test ID)
   │  • Post-Migration Validation (checklist/test ID)
   │  • Owner Contact (who approves this wave)
   │  • Dependencies on non-migrated systems
   └─ Ensure ALL application rows are complete (no blanks in key fields)

Step 4: Re-Upload Revised CSV
   └─ Transform console → "Re-upload wave plan" → proceed to next gate

Step 5: Approval Gate: "Review migration waves"
   └─ AWS team administrator reviews + approves before execution begins

RECEIVING STORY (WAVE PLAN):

The wave plan story receives:
   → Approved CSV wave plan (with customizations)
   → Approved CSV inventory (with instance types)

Wave plan story then:
   → Converts CSV into detailed execution plan
   → Creates Jira/project timeline for each wave
   → Assigns cutover coordinators + validation owners
   → Schedules test cutover windows
   → Prepares rollback procedures per wave

================================================================================
DATA INTEGRITY & COMPLETENESS
================================================================================

CRITICAL: Transform only includes rows in the actual migration if BOTH fields 
are populated:
   • Application (not blank)
   • Application Wave (not blank)

Before approval, verify:
   ✓ All servers intended for migration have application name
   ✓ All applications have a wave assignment (Wave 1, 2, 3, 4)
   ✓ No unintended "blank rows" that would be dropped
   ✓ All 30 Windows 2008 R2 servers are in the plan (check line count)

If issues found:
   → Edit CSV to add missing application/wave data
   → Re-upload corrected version
   → Transform re-validates on next gate attempt
